# libefs internals

This document describes how libefs works internally. It is written for
people who want to change or debug the library. For the public API see
[manual.md](./manual.md); for known problems see
[review-findings.md](./review-findings.md).

All addresses refer to version 1.0.0 as built by `make` (see
`build/lib/lib-efs.map`).


## 1. Source layout

| File | Segment(s) | Contents |
| ---- | ---------- | -------- |
| `src/lib/lib-efs.i` | – | constants, error codes, flag bits, EAPI addresses, `efs_directory` and `libefs_config` structs, zero page names |
| `src/lib/config.i` | – | build option `SHOW_INDICATE_ACTIVITY` (border colour flashing while loading/saving/searching) |
| `src/lib/lib-efs.s` | `EFS_CALL`, `EFS_ROM` | ROM jump table, init, util/setnam/load/open/close/chrin bodies, `efs_readef` reader, config access, command parsing, file load/verify, directory search |
| `src/lib/lib-efs-ram.s` | `EFS_RAM` | the 128 bytes copied to `$df00`: public jump table, bank in/out trampolines, the self-modifying "generic command" buffer, state variables |
| `src/lib/lib-efs-minieapi.s` | `EFS_MINIEAPI` | read-only EAPI replacement copied to `$df80` |
| `src/lib/lib-efs-rw.s` | `EFS_ROM_RW` | save, chrout, close of a written file, scratch, format, defragment, free-space checks |
| `src/lib/lib-efs-space.s` | `EFS_ROM` | size and blocks-free calculation |
| `src/lib/lib-efs-dirlist.s` | `EFS_ROM` | `$` directory listing generated byte by byte by a state machine |
| `src/lib/lib-efs.cfg` | – | linker config: `$8000-$803f` call table, `$8040-$9fff` ROM code, load images for `$df00` and `$df80` |

Built library (`build/lib-efs.prg`): `$8000-$9761`, i.e. it fits in ROML
of bank 0. `EFS_ROM` occupies `$8040-$8f0b`, `EFS_ROM_RW` `$8f0c-$9661`,
followed by the load images of the IO2 code (`$9662`, 128 bytes) and
MiniEAPI (`$96e2`, 126 bytes).


## 2. Memory model and banking

### 2.1 Cartridge

```
bank 0 ROML $8000-$9fff   libefs (this library)
bank 0 ROMH $a000-$b7ff   area 0 directory (read-only EFS)
            $b800-$baff   EAPI (am29f040 driver, 768 bytes)
            $bb00-$bb17   EasyFlash cartridge name ("ef-nAME:" + 16 chars)
            $bb18-$bb3f   libefs configuration (40 bytes)
            $bc00-$bfff   startup code / loader (test cartridge)
bank 1..   area 0 files
bank n..   area 1 / area 2 (read/write), positions from the config
```

### 2.2 The IO2 page (`$df00-$dfff`)

The EasyFlash has 256 bytes of RAM in the IO2 area. It is the only RAM
libefs uses besides 11 zero page bytes. The library runs from ROM, so a
small trampoline in IO2 is needed to switch the ROM in and out.

`$df00-$df7f` (`EFS_RAM`, copied by `EFS_init`):

| Address | Name | Purpose |
| ------- | ---- | ------- |
| `$df00` … `$df2a` | `EFS_util` … `EFS_chrout` | public entries, each `jsr efs_bankin` + `jmp rom_xxx_body` |
| `$df30` | `EFS_readst` | `lda #status; rts` – `status_byte` is the immediate operand |
| | `efs_bankin` | saves `$01` into `backup_memory_config`, sets `$01` to `memory_byte` (`$37`), falls into `efs_enter` |
| | `efs_bankout` | restores `$01`, writes `EASYFLASH_KILL` (`$04`) to `$de02` (cartridge off), `pla`, `rts` |
| | `efs_generic_command` | 14 byte buffer for self-modifying code (see 2.3) |
| | `efs_io_byte` | `jsr EAPIReadFlashInc` (operand patched to WriteFlashInc / WriteFlash / EraseSector) followed by `efs_enter_pha` |
| | `efs_enter` | `$de00 = 0`, `$de02 = $87` (16k + LED), `pla`, `rts` |
| | data | zero page backup (11 bytes), `error_byte`, `efs_flags`, `internal_state`, `filename_address`, `filename_length`, `io_start_address`, `io_end_address` |

`$df80-$dfff` is EAPI's jump table area: either the real EAPI jump
table (installed by EAPIInit when `EFS_init_eapi` is used) or MiniEAPI.

All public calls work like this:

```
user: jsr $df0c (EFS_load)
  $df0c: jsr efs_bankin      ; $01=$37, bank 0, 16k mode -> libefs ROM visible
         jmp rom_load_body   ; executes in ROML bank 0
  rom_load_body ... jmp efs_bankout ; $01 restored, cartridge killed, rts to user
```

On exit the cartridge is always switched off (`$de02 = $04`), whatever
the mode was on entry.

**Invariant:** while code in `$8000-$bfff` runs, `$de00` must be 0. Every
access to another bank goes through code in IO2 that switches the bank,
does the access and returns through `efs_enter`/`efs_enter_pha`, which
switches back to bank 0.

### 2.3 Self-modifying "generic command"

`efs_generic_command` (14 bytes) is filled with one of several small
routines, depending on the operation:

| Init function | Code | Used for |
| ------------- | ---- | -------- |
| `efs_init_readef` | `lda #bank; sta $de00; lda abs; jmp efs_enter_pha` + 3 spare bytes | reading directory / flash data with a free pointer (`efs_readef`) |
| `efs_init_readef_rely` | same with `lda abs,y` | defragment copy |
| `efs_init_readmem` | `jsr efs_bankout; lda (zp_var_xe),y; ldx memory_byte; stx $01; jmp efs_enter_pha` | reading the C64 RAM under the caller's memory config (save, verify) |
| `efs_init_eapi_body` | `jsr efs_bankout; sta $xx00,x; jmp efs_enter_pha` | copying EAPI to RAM that may be under ROM |

`efs_readef_bank`, `efs_readef_low/high` are the operand bytes of that
code. The three spare bytes are `efs_readef_storedbank/addr` and are
used by `efs_readef_swap` (defragment alternates between directory and
data pointers). `status_byte - 1` and `status_byte + 1` (the `lda #` and
`rts` around the status operand of `EFS_readst`) are used as temporary
variables `efs_temp_var1/2` during defragmentation and restored by
`efs_finish_tempvars`.

`efs_setstartbank_ext` temporarily patches the 6 bytes in front of
`efs_bankout_end` into `jsr EAPISetBank; jmp efs_enter_pha`, calls it and
restores the original bytes from the ROM image.

### 2.4 Zero page

`$35-$3f` (`zp_var_x5` … `zp_var_xf`) are saved to `backup_zeropage_data`
and zeroed by `backup_zeropage`, and restored by `restore_zeropage`.
Only `rom_open_body`, `rom_load_body`, `rom_save_body` and
`rom_dirload_chrin` do this. Common usage:

| ZP | Usage |
| -- | ----- |
| `$35/$36` | pointer to the active configuration (`$bb18` or the default config in ROM) |
| `$37` | temp / banking mode |
| `$38` | command character / bank / name match result |
| `$39/$3a` | file offset (or max space) |
| `$3b-$3d` | 24 bit size |
| `$3e/$3f` | name pointer / RAM pointer |


## 3. Configuration

`rom_config_prepare_config` checks for the text `LIBEFS` at `$bb18`. If
found, `$35/$36` points there, otherwise to `efs_default_config` at
`$8018` (read-only, area 0 at `00:$a000`). Values are read with
`rom_config_get_value` (A = offset in `libefs_config`).

Layout (offset from `$bb18`, see `lib-efs.i`):

| Offset | Field |
| ------ | ----- |
| 0-5 | `LIBEFS` |
| 6-8 | version (unused in cartridge config) |
| 9 | `areas`: 1 = read-only, 3 = with two r/w areas |
| 10-15 | area 0: dir bank, dir high, files bank, files high, size, bank mode |
| 16-21 | area 1 |
| 22-27 | area 2 |
| 28 | `dfcall`: call defragment callbacks |
| 29/30 | defragment warning vector |
| 31/32 | defragment all-clear vector |
| 33-35 | activity indicator (not implemented) |
| 36-39 | unused |

**Active area detection** (`rom_config_prepare_config` together with
`rom_config_checkarea`): if the flags byte of the first directory entry
of area 1 is not `$ff`, area 1 is active. Otherwise area 2 is checked
the same way. If both are empty, area 1 is used.

### 3.1 `efs_flags`

| Bit | Meaning |
| --- | ------- |
| 0 | `LIBEFS_FLAGS_RELOCATE` – load to X/Y (set by util/setlfs with SA 0) |
| 1 | `LIBEFS_FLAGS_VERIFY` – set by `EFS_load` with A≠0 |
| 4,5 | area of the found file (`$30` = area 0, `$10` = area 1, `$20` = area 2). The comment in `lib-efs.i` says bits 5/6, which is wrong. |
| 6 | current area is 1 |
| 7 | current area is 2 |

The `rom_config_get_area_xxx`, `_invert` and `_active_file` functions
read a field of the area selected by bits 6/7, of the other r/w area, or
of the area the found file lives in.

### 3.2 `internal_state`

| Value | Meaning |
| ----- | ------- |
| `$00` | no file open |
| `%10xxxxxx` | file open for reading (chrin) |
| `%11xxxxxx` | file open for writing (chrout) |
| `%01ssssss` | directory open for reading; `ssssss` is the dirlist state |
| `$01` (`STATE_COMMAND_DONE`) | a command (scratch) finished the operation; only close is valid |


## 4. Directory format

Each area has a directory of `$1800` bytes = 256 entries of 24 bytes
(`efs_directory`):

| Offset | Field |
| ------ | ----- |
| 0-15 | name, padded with `$00` |
| 16 | flags: bits 0-4 type (`$1f` = empty/terminator, `$00` = deleted, `$01` = prg), bit 7 hidden |
| 17 | bank |
| 18 | reserved (bank high) |
| 19/20 | offset in bank (relative to the area's `files high` address) |
| 21-23 | size (24 bit, including the 2 byte load address) |

libefs writes new entries with flags `$61`. Scratching programs the
flags byte to `$60` (flash can only clear bits), so `flags & $1f`
becomes 0.

R/W areas: the directory is at `dir bank : dir high`. Files start
`$1800` bytes after `files high` in `files bank`, and the file data are
stored sequentially. The banking mode (`$d0` lhlh, `$b0` llll, `$d4`
hhhh) defines how a pointer continues at the end of a bank. That is the
same encoding EAPI's `EAPISetPtr` uses: `mode & $e0` is the high byte
where the bank ends, `mode << 3` is the high byte where the next bank
starts.


## 5. Operations

### 5.1 Init

* `EFS_init` (`$8000`) copies 128 bytes to `$df00`.
* `EFS_init_eapi` (`$8003`, A = target page) checks for `eapi` at
  `$b800`, copies 3 pages through the generic command (so the target may
  be RAM under ROM), patches the generic command into
  `jsr target+$14` (EAPIInit) and calls it.
* `EFS_init_minieapi` (`$8006`) copies MiniEAPI to `$df80`.

### 5.2 Directory search (`efs_directory_search`)

Searches area 0, then area 1, then area 2 (only areas 0 if `areas`≠3).
For every entry `rom_dirsearch_checkname` compares the name (`*` matches
the rest, `?` one character, a shorter name must be followed by `$00`).
Then the flags byte is read: `flags & $1f == $1f` ends the search
(terminator), `== 0` skips the entry. On a match the entry's bank,
offset and size are loaded into `$38-$3d` and bits 4/5 of `efs_flags`
record the area. A file in area 1 or 2 sets `status_byte = $80`.

### 5.3 Load / verify (`rom_load_body`)

1. Store X/Y as `io_start_address`; A≠0 sets the verify flag.
2. Back up the zero page, check `internal_state` = 0.
3. `rom_command_begin` parses a leading `X:` / `Xn:` command (only `$`
   is accepted for load; it creates the directory listing via the
   dirlist state machine).
4. `efs_directory_search`, `rom_fileload_begin` (`EAPISetPtr`, `EAPISetLen`,
   `EAPISetBank`), `rom_fileload_address` (first two bytes; relocation if
   the flag is set), then `rom_fileload_transfer` / `rom_fileload_verify`
   using `efs_io_byte` (= `EAPIReadFlashInc`).
5. X/Y = address of the last byte written (not +1 like the KERNAL).

### 5.4 Open / chrin / close

`rom_open_body` sets `internal_state` to read (`$80`) or write (`$c0`),
then handles commands: `$` → directory state, `S` → scratch,
`@` → scratch before writing. A read open runs `efs_directory_search` +
`rom_fileload_begin`, after which `EFS_chrin` just calls `efs_io_byte`
(no zero page needed). A directory chrin runs one step of the dirlist
state machine (with zero page backup).

### 5.5 Save (`rom_save_body`)

1. `rom_filesave_conditions`: r/w areas must exist. It then checks
   *max space − used space (live files) − new size* (disk full if
   negative), rejects start = end, and checks *free directory entries* and
   *max space − blocked space (live + deleted files)*. If the last two
   checks fail, a defragmentation is done automatically and the checks
   are repeated.
2. Commands: `@` scratches an existing file.
3. If the name exists: `ERROR_FILE_EXISTS`.
4. `rom_filesave_begin` walks to the first free directory entry
   (`rom_filesave_nextentry`) and computes the bank/offset after the
   last file (end of last entry = offset + size, converted to
   bank/offset for the area's banking mode).
5. `rom_filesave_transfer_dir` writes name, flags (`$61`), bank,
   reserved, offset. `rom_filesave_transfer_dir_size` writes the size.
   `rom_filesave_transfer_data` writes the load address and the data
   read from C64 RAM via `efs_readmem` (C64 memory config of the caller).

### 5.6 Write via chrout

`rom_filesave_chrin_prepare` (called by open with A=1) checks the space
for an assumed size of `$2000` bytes, writes the directory entry except
the size, and stores the address of the size field in
`filename_address` and the directory bank in `filename_length`.
`io_start_address`/`io_end_address` low form a 24 bit byte counter.
`io_end_address+1` holds the bank at which the area ends, for overflow
detection. Every `EFS_chrout` writes one byte with `EAPIWriteFlashInc`
and increments the counter. `EFS_close` writes the 3 size bytes into
the directory entry (`rom_filesave_transfer_dir_finish`). Until close
the size field is `$ffffff`.

### 5.7 Scratch

`rom_scratch_process` programs the flags byte of the found entry with
`$60` (refused in area 0 with `ERROR_WRITE_PROTECTED`). The space is
freed only by the next defragmentation.

### 5.8 Defragment and format

`rom_defragment_copy` (X = old area, Y = new area) walks the old
directory. Each live entry is copied to the next free entry of the new
directory with a new bank/offset (`rom_defragment_copy_dir`), and its
data are copied byte by byte (`rom_defragment_copy_data`).
`efs_readef_swap` switches the read pointer between directory and data.
It calls the user's warning callback once per file and once per 256
bytes written, and the all-clear callback at the end. Then
`rom_defragment_erasearea` erases the old area sector by sector
(size/8 sectors of 64K). `EFS_format` erases both r/w areas.

### 5.9 Directory listing

`lib-efs-dirlist.s` generates a BASIC-program-like listing byte by byte.
The state number lives in `internal_state` bits 0-5 (and in `$37` while
running); `io_end_address` is reused as area and sub-state counters.
States 1-19 are the header line, 29-45 one file line, 20-28 the
"blocks free" line and the end. `rom_dirload_sm_linenend` advances to
the next listed entry (skipping deleted, hidden, non-matching), moving on
to area 1 and 2 at the end of each directory. Files in area 0 are shown
with `<` (write protected). Blocks free = (max space − used space)/256 − 1
of the active area.


## 6. Testing notes

The test cartridge (`make`, `build/test-libefs.crt`) uses `BANKMODE`
from the Makefile (`ll` by default): area 1 is `llll` in banks 32-63
ROML, area 2 is `hhhh` in banks 32-63 ROMH. With `BANKMODE=lh` both areas
are `lhlh` (banks 32-47 and 48-63). The two layouts behave differently
in defragmentation, see the findings document.
