  + use the one from codc-easyflash

- rename command (next version)
- support open with "command0:filename,w,p" notation; support the w for
  write, r for read; p only for prg type (next version)

- commit marker for file data: a save interrupted by a power loss leaves
  a directory entry that looks valid with a $ff tail; a marker bit
  written last would make such entries recognisable (EFS_validate could
  then scratch them); see docs/review-findings.md S22

- EFS_validate does not check or erase unused banks (some hardware and
  older software implementations do not clear them)

- validate the configuration at EFS_init (area sizes, same bank/address
  for directory and files of an area; see the limits in docs/manual.md)

- faster load loop: a dedicated banked read loop in non-bankable RAM
  instead of EAPIReadFlashInc per byte could roughly halve load times
  (about 190 cycles per byte now); SHOW_INDICATE_ACTIVITY costs another
  ~18 cycles per byte and should be 0 for a release build

- "@0:" overwrite: the space check runs before the old file is scratched,
  so replacing a large file on a nearly full area fails although it
  would fit afterwards (kept on purpose: a failing overwrite never loses
  the old file); see S18
